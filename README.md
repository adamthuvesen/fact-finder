# Agentic Research Loop

![License](https://img.shields.io/github/license/adamthuvesen/agentic-research-loop) ![Python](https://img.shields.io/badge/python-3.13%2B-blue)

A research kit for bounded investigations. Give it a question and a set of read-only
sources. It creates a workspace, frames the case, and validates the evidence the
investigation leaves behind.

Execution runs inside your agent client's native `/goal`. The client owns persistence
and continuation. This repo owns the research contract, read-only source access, durable
artifacts, and deterministic validation. There is no subprocess runner and no second
agent loop. [The decision record](.agents/docs/decisions/native-goals.md) explains why.

## Quick start (no API keys, no MCP)

```bash
uv sync --dev

uv run research init export-reliability --template root-cause \
  --question "Why did the weekly batch-export success rate drop in March 2026?" \
  --local-only --context-path examples/local-sources

uv run research goal export-reliability
```

The last command prints a `/goal ...` block. Paste it into Claude Code or Codex from the
repo root. The investigation runs to completion in that session and ends with strict
validation. The finished result of this case is in
[`examples/demo-export-reliability/`](examples/demo-export-reliability/).

## Run inside Claude Code or Codex

Submit one native goal from the repository root. Claude Code names the skill as
`the research-goal skill`, and Codex names it as `$research-goal`:

```text
/goal Use the research-goal skill to investigate:

Why did the weekly batch-export success rate drop in March 2026? Use only the local files under examples/local-sources. Stop when the largest cause is named with reconciling numbers and strict validation passes.
```

For an ambiguous, causal, cross-source, or high-stakes question, name `research-spec`
instead. It runs targeted discovery and designs falsifiable hypotheses first.

## Case artifacts

Each case lives in `research/<date>-<slug>/`: `brief.md` (binding question and scope),
`notes.md` (working record, no gate), `report.md` (the answer), `queries.sql`,
`source-objects.md`, `evidence.json` (sources, claims, checked calculations), `review.json`
(the independent challenge, bound by hash), and an optional `plan.md`.

## The completion gate

A case is done when `research validate --strict` passes.
[docs/evidence-contract.md](docs/evidence-contract.md) lists what it checks. It proves
integrity and arithmetic. It cannot prove semantic truth or reviewer independence, and
its output says so. Independent challenge covers what a gate cannot.

## Sources

Every bundle is read-only and names its control. Some upstream servers
are read+write unless you supply a read-only account or scoped key. Each bundle's
`SETUP.md` says which case it is. Only web search is built in. Local files attach per
case with `--context-path`. These bundles are opt-in, and the
[catalog](examples/sources/README.md) describes each one:

config and write-tool deny list from one definition.

## CLI

`uv run research --help` lists every command. `gsc` and `ga4` need `GSC_SITE` and
`GA4_PROPERTY_ID`, with no default.

## Use from another repo

Add this package as a dependency pinned by git SHA. Add a `[tool.agentic-research-loop]`
table to your `pyproject.toml`, then run `uv run research setup`. It links the skills
into `.agents/skills` and writes client configs. Bundles under your `examples/sources/`
override packaged ones of the same name. Set `gsc_site` and `ga4_property_id` in that
table, or use the environment variables, which win.

## Development

`make check` is the gate. CI runs it too. [AGENTS.md](AGENTS.md) lists which check
enforces which rule. Client goal behavior is an external dependency, so
[`evals/native-goal/`](evals/native-goal/README.md) holds a blind, keyless canary.
