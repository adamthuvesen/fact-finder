# Source bundles (opt-in)

Each subdirectory is a source you can enable. The committed `.mcp.json` stays neutral, so
you wire only the sources you use.

| File | What it is |
| --- | --- |
| `source.json` | The registry spec, including the named `read_only_control` |
| `mcp.snippet.json` | One server definition. Absent for a `cli` or `native` source such as GSC. |
| `SETUP.md` | Credentials, and how read-only is enforced |

```bash
uv run research source enable github   # registers it and generates every client's config
uv run research source list
uv run research doctor                 # checks config against each read-only control
uv run research source disable github
```

`read_only_control.mechanism` comes from a closed set. `url_suffix`, `server_flag`,
`arg_absent`, and `statement_allowlist` are checked from config. `credential_scope`,
`credential`, and `native` are declared only, because they live outside any file here.

### Warehouses and databases

Query Azure via the official Azure MCP Server in read-only mode: Azure Monitor / Log Analytics (KQL over logs and metrics), Azure SQL, Azure Data Explorer (Kusto/ADX), Cosmos DB, and Storage. The Microsoft-cloud equivalent of Snowflake/BigQuery (warehouse) plus Datadog (observability). Read-only — the server runs with --read-only (write tools filtered out); list resource groups and resources to discover scope before querying. - **[BigQuery](bigquery/SETUP.md)** (`bigquery`, http-oauth; read-only: credential, `BigQuery Data Viewer`). BigQuery for live metrics and warehouse-backed evidence (incl. GA4/GSC exports). Denied write tools: `execute_sql`. Query BigQuery via the Google-managed BigQuery MCP server. Discover datasets and tables live before querying. Prefer the read-only query path (execute_sql_readonly); read-only is ultimately enforced by IAM — grant BigQuery Data Viewer + Job User + MCP Tool User (roles/mcp.toolUser), no Data Editor (see SETUP.md). SELECT-only; never run DML/DDL. If GA4 or GSC BigQuery exports exist, query them here as the default analytics path.
- **[Databricks](databricks/SETUP.md)** (`databricks`, http-oauth; read-only: url_suffix, `/api/2.0/mcp/genie`). Databricks (Genie) for warehouse metrics over Unity Catalog tables — read-only NL/SQL queries. Query Unity Catalog tables via the Databricks managed Genie MCP server — ask analytical questions in natural language; Genie generates and runs read-only SQL and returns the results plus the SQL. Read-only by design (Genie has no write path). Prefer this over the Databricks SQL MCP server, which is read+write and guarded only by Unity Catalog grants. Queries run under your UC identity, so UC permissions and lineage apply.
- **[DuckDB](duckdb/SETUP.md)** (`duckdb`, stdio; read-only: arg_absent, `--read-write`). DuckDB for local analytical queries over files and embedded databases. Query a local DuckDB database or files (CSV/Parquet) via the MotherDuck MCP server, opened read-only. Discover objects live (SHOW TABLES / DESCRIBE) before querying — do not assume a schema. SELECT-only: the database is opened without --read-write. Good for ad-hoc analysis of exports without standing up a warehouse.
- **[Postgres](postgres/SETUP.md)** (`postgres`, stdio; read-only: server_flag, `--access-mode=restricted`). Postgres for live metrics and application-database evidence. Query a Postgres database via Postgres MCP Pro in restricted (read-only) mode. Discover objects live before querying — list schemas and tables, inspect columns — do not assume a schema. SELECT-only: the server parses each statement and runs it in a read-only transaction. Prefer explicit column lists and bounded result sets over SELECT *.
- **[Redshift](redshift/SETUP.md)** (`redshift`, stdio; read-only: native, `BEGIN READ ONLY`). Redshift for warehouse metrics — schema discovery and read-only SQL over clusters and serverless. Discover databases, schemas, tables, and columns and run read-only SQL over Redshift clusters and serverless workgroups via the official AWS Labs Redshift MCP server (Data API). Read-only is engine-enforced: every query runs inside a BEGIN READ ONLY transaction and the server exposes no write tools. Discover objects live before querying; SELECT-only.
